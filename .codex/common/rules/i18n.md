# Internationalization Rules

Apply these rules when adding or changing user-facing text in a project that already uses i18n.

## Follow Existing Conventions

- Inspect nearby translation calls and the relevant locale resources to identify the existing library, key structure, namespaces, source locale, and fallback policy.
- Use the existing translation mechanism for labels, buttons, placeholders, validation messages, notifications, empty states, and accessibility text. Do not hardcode new user-facing copy in components or logic.
- Reuse an existing key when its meaning and context match. Create a new key when changing a shared key would alter unrelated screens.
- Follow the project's key naming, resource format, and translation generation workflow. Do not edit generated resources directly.
- Do not introduce an i18n library or migrate existing text as part of an unrelated task when the project does not already use i18n.

## Write Translatable Messages

- Write complete messages and use named interpolation parameters for dynamic values. Avoid assembling sentences from translated fragments or embedding user data in translation keys.
- Use the existing i18n system's plural and grammatical selection features instead of assuming one language's word order or plural rules.
- Format dates, times, numbers, and currencies through the project's locale-aware utilities using the active locale and applicable timezone or currency.
- Keep interpolation names and required message variants consistent across locale resources.

## Update And Verify

- Update the source locale and other locales required by the project's translation policy. If translations are managed separately, preserve that workflow and report pending translations without inventing completed translations.
- Check affected keys, placeholders, plural variants, and fallback behavior with the project's existing i18n checks when available.
- When verifying the changed UI, check the affected text for raw keys, missing translations, and layout issues caused by longer translations or supported right-to-left layouts.
